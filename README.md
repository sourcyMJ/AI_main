# Workbench — агенты и дисциплина

Плагин Claude Code: четыре субагента и три скилла. Ставится на машину один
раз и работает во всех локальных проектах — вместо копирования файлов в
каждый репозиторий руками.

## Установка

```
/plugin marketplace add sourcyMJ/AI_main
/plugin install workbench@sourcymj
```

После правок в этом репозитории:

```
/plugin marketplace update sourcymj
```

## Что внутри

| Компонент | Модель | Роль |
|---|---|---|
| `scout` | sonnet | Разведка: найти, где что лежит, собрать факты. Read-only |
| `grunt` | opus | Массовые механические правки по однозначной инструкции |
| `deep-worker` | fable | Задача требует рассуждения, но съела бы контекст главной сессии |
| `verifier` | opus | Приёмка: сверяет артефакт с отчётом. Намеренно без Edit |

| Скилл | О чём |
|---|---|
| `agent-orchestration` | Что оставить себе, что отдать, почему приёмку делает отдельный агент |
| `planning-discipline` | Прочитать перед правкой, план до кода, самопроверка, честный отчёт |
| `nashdom-declarations` | Единственный рабочий способ сбора проектных деклараций с наш.дом.рф |

## Приёмка включается сама

Главное в плагине — не агенты, а то, что приёмку **нельзя забыть**.

В плагине два хука. Их исполняет сам Claude Code, а не модель, поэтому
пропустить их она не может:

| Хук | Когда | Что делает |
|---|---|---|
| `PostToolUse` на Edit/Write | После правки файла | Ставит отметку, что в этом ходе что-то менялось |
| `Stop` | Когда Claude собирается закончить ход | Если отметка есть — не отпускает, пока не прогнан `verifier` |

Зацикливания нет: отметка снимается сразу, а `verifier` — read-only агент
без Edit, новой отметки он не поставит. Если после приёмки Claude снова
что-то правит, приёмка повторяется — и это правильно.

Ход без правок кода проходит без приёмки: вопрос, поиск, объяснение
ничего не тормозят.

Хуки ничего не стоят в контексте — `plugin details` показывает их как
`harness-only — no model context cost`.


Постоянная стоимость — около 770 токенов на сессию: это только описания,
по которым Claude решает, что звать. Тело скилла или агента читается
только когда он действительно сработал.

## Чего плагин не делает

**1. Не задаёт модель и переменные окружения.** По документации плагинов
его `settings.json` принимает только `agent` и `subagentStatusLine`.
Поэтому выбор Opus на входе и пол для субагентов задаются отдельно — один
раз в `~/.claude/settings.json`, и это действует во всех локальных
проектах:

```json
{
  "model": "opus",
  "env": { "CLAUDE_CODE_SUBAGENT_MODEL": "sonnet" }
}
```

**2. Не доезжает до облачных сессий.** Плагин, поставленный через
`/plugin install`, живёт только в локальном CLI и в claude.ai/code не
синхронизируется. Облачная сессия читает то, что лежит в самом
репозитории — `.claude/agents/` и `.claude/skills/`. Поэтому в проектах,
которые работают в облаке, копии этих файлов остаются в репозитории
проекта; канон — здесь.

## История

Плагин вырос из `.claude/agents/` репозитория `Rent_intermark_search` и
вынесен сюда через `git subtree split` с сохранением истории: агенты и их
правила — общие, а тот репозиторий про аренду.
