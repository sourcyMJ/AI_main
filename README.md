# Workbench — агенты и дисциплина

Плагин Claude Code: четыре субагента и два скилла, которые до этого
приходилось копировать в каждый проект руками.

## Что внутри

| Компонент | Модель | Роль |
|---|---|---|
| `scout` | sonnet | Разведка: найти, где что лежит, собрать факты. Read-only |
| `grunt` | opus | Массовые механические правки по однозначной инструкции |
| `deep-worker` | fable | Задача требует рассуждения, но съела бы контекст главной сессии |
| `verifier` | opus | Приёмка: сверяет артефакт с отчётом. Намеренно без Edit |
| скилл `planning-discipline` | — | Дисциплина работы над нетривиальной правкой |
| скилл `nashdom-declarations` | — | Единственный рабочий способ сбора ПД с наш.дом.рф |

## Установка

```
/plugin marketplace add sourcyMJ/Rent_intermark_search
/plugin install workbench@sourcymj
```

Обновление после правки в репозитории:

```
/plugin marketplace update sourcymj
```

## Чего плагин НЕ покрывает — важно

**1. Модель по умолчанию и переменные окружения.** Файл `settings.json`
внутри плагина поддерживает только `agent` и `subagentStatusLine`. Полей
`model` и `env` там нет. Поэтому выбор Opus на входе и пол для субагентов
по-прежнему задаются отдельно — один раз в `~/.claude/settings.json`,
чтобы правило действовало во всех локальных проектах:

```json
{
  "model": "opus",
  "env": { "CLAUDE_CODE_SUBAGENT_MODEL": "sonnet" }
}
```

**2. Облачные сессии.** Плагин, установленный через `/plugin install`,
живёт только в локальном CLI и в claude.ai/code не синхронизируется. В
облачном контейнере подхватывается то, что лежит в самом репозитории
(`.claude/agents/`, `.claude/skills/`) плюс скиллы, включённые в
claude.ai → Settings.

Поэтому в репозитории лежат копии: агенты в `.claude/agents/`, скиллы в
`.claude/skills/`. Они нужны облаку. Канон — этот каталог
(`agents-plugin/`), копии обновляются следом, а `.claude/cloud-setup.sh`
при старте сверяет их и сообщает о расхождении.

Плагин снимает копипасту между **локальными** проектами, а не между
облаком и Маком.
