# Оркестрация: что оставить себе, что отдать

Главная сессия — Opus. Она принимает задачу и **решает распределение**, а не
выполняет всё сама и не отдаёт всё сразу.

Критерий один: **отдавай объёмное и шумное, оставляй себе решающее.**

## Что не делегируется никогда

Решения, план, архитектура, синтез чужих результатов, тексты наружу
(отчёты, описания, правила), разбор противоречий между источниками. Цена
ошибки здесь высокая, а экономия на модели копеечная.

Если задача — выбрать между двумя архитектурами, это не делегируется. Если
задача — прочитать двадцать файлов ради трёх фактов, это `scout`.

## Кого звать

| Агент | Когда |
|---|---|
| `scout` | Найти, где что лежит; собрать факты; прочитать логи; обойти много файлов. Возвращает сводку с адресами `файл:строка`, а не сырые выдачи. Read-only |
| `grunt` | Массовые механические правки по **однозначной** инструкции — когда решение уже принято. Неоднозначная инструкция — не его случай |
| `deep-worker` | Нужно рассуждение, но задача съела бы контекст главной сессии: разбор большого файла, анализ незнакомой кодовой базы, проработка варианта |
| `verifier` | Приёмка перед выдачей результата пользователю |

Независимые задачи запускать **одним сообщением**, чтобы они шли
параллельно, а не по очереди.

## Приёмка обязательна

Перед тем как отдать результат пользователю — прогнать `verifier`. Особенно
если работу делал субагент.

Он проверяет **не рассуждения, а артефакт**: открывает код, дифф, вывод
команды и сверяет с тем, что о них сказано. Расхождение отчёта и кода —
находка первой категории.

**Самопроверку приёмкой не считать.** Тот, кто писал, перечитывает свой же
ход мысли и повторяет ту же слепую зону. Приёмку делает отдельный агент с
чистым контекстом, которому известны только требование и артефакт. Поэтому
`verifier` намеренно лишён Edit: его ценность во взгляде со стороны.

В задании на приёмку перечисляй **заявленное по пунктам** — что именно
утверждается о работе. Приёмщик ищет расхождения с этим списком, а не
«что-нибудь не так».

## Где каскад «дёшево → проверка → дорого» работает, а где нет

Работает только там, где есть **внешний детерминированный** критерий: код
компилируется, тесты проходят, JSON по схеме, SQL выполняется, цифра
сошлась с эталоном. Тогда дешёвая модель делает, критерий ловит промах,
дорогая разбирает спорное.

Для задач без такого критерия — отчёт, формулировка, выбор решения —
каскад не применять. Модель не умеет оценить, что не справилась: она
просто сделает хуже, и это будет выглядеть нормально.

## Модели задаются не здесь

У каждого агента модель прибита в его frontmatter. Модель главной сессии и
пол для субагентов живут в `settings.json` (`{"model": "opus"}` и
`CLAUDE_CODE_SUBAGENT_MODEL`) — плагин их задавать не умеет.

Везде алиасы (`opus`, `sonnet`, `fable`), а не полные ID: алиас сам
переедет на следующую версию, прибитый ID через квартал устареет молча.
